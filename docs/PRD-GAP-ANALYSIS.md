# PRD Gap Analysis — Smart Appointment Scheduler

Generated by reviewing the codebase (`app/`, `routes/`, `resources/views/`, `database/`) against
the PRD. Legend: **✅ Built** · **🟡 Partial** · **❌ Missing**.

**Overall:** the *Core scheduling system* is largely in place (~60–70% of §5.1), the **entire AI
layer (§5.2) is not built**, almost all **integrations/messaging/payments are not built**, and the
**§5.3 roadmap** is untouched (as intended). The **data model (§7) is ~100% present** — many tables
exist but are not yet driven by UI/logic (reminders, intake, payments, AI logs).

## §5.2 AI Features — **entirely missing (❌)**

None of the AI layer is implemented. The only AI-adjacent piece is **rule-based no-show scoring**
(`NoShowPredictor`), which the PRD explicitly requires *as the fallback* — so the fallback exists,
but no actual AI provider does.

Missing: No-show prediction (AI), Smart waitlist, Auto cancellation fill, Slot recommendation,
Load balancing, Overbooking optimization, Demand-based scheduling, Natural-language booking,
AI scheduling assistant (chatbot), Intake summarization, Smart symptom routing, Smart reminder
generation, Real-time translation, Sentiment & feedback analysis, Predictive analytics,
Natural-language report queries, Smart follow-up suggestions. The `ai_request_logs` table exists
but is never written to.

## §5.3 Future / Roadmap — **not started (❌, expected)**

Native mobile apps, voice booking, AI voice agent, kiosk mode, predictive capacity planning,
care-gap recall, deep EHR write-back, full RCM, pharmacy/lab scheduling, referral management,
provider marketplace, group/class scheduling, white-label multi-tenant SaaS.

| Stage / Mechanism | Status | Notes |

> This is the biggest functional gap relative to the PRD's stated **primary objective**: the
> prediction *score* exists, but the **confirm → remind → re-fill automation loop is not built**.

## Priority recommendations (to close the highest-value gaps)

1. **No-show automation loop (§6)** — the product's headline goal. Build: reminder generation +
   Laravel Scheduler cadence (booking → 72h → 24h → 2h) + a notification channel (start with email
   via SMTP, which needs no paid account), confirmation links, and smart-waitlist auto-fill on cancel.
2. **Provider availability + holidays UI** — so working hours/breaks/exceptions are editable, not seed-only.
3. **Multi-tenant clinic scoping** — scope all queries by `clinic_id` for clinic admins/staff.
4. **Intake forms + digital check-in** — wire up the existing `intake_forms` table with a form + e-sign.
5. **Payments (Stripe)** — copay at booking, refunds/cancellation fees.
6. **AI layer (§5.2)** — start with NLP booking + intake summarization + AI no-show scoring,
   keeping the rule-based fallback and logging every call to `ai_request_logs`.
7. **Reporting export (CSV/PDF)** and **REST API + Sanctum tokens**.
8. **Security hardening** — PHI encryption at rest, 2FA, broaden audit coverage.
